# VERIFICATION.md — what "verified" means in Compact, tier by tier

Every optimization Compact returns carries a verification verdict.  This
document defines, precisely, what each verdict level proves, where each
prover's coverage ends, and what happens when a prover cannot decide.
Every boundary claim in the table is backed by a named, passing test in
`tests/test_tier_boundaries.py` — if the code and this table ever
disagree, that is a release blocker, not a documentation bug.

The public entry point is `compactq.verify(original, optimized)`; it
returns `{equivalent, tier, method, global_phase_ignored, runtime_ms}`.
`tier` is part of the stable API — callers may require a minimum grade
(`assert result["tier"] >= 2`).

## The guarantee all tiers share

All tiers decide equivalence **up to global phase**: `U ≈ e^{iφ}·V`.
This is the physically meaningful equivalence for circuits and is stated
in every result (`global_phase_ignored: True`).

## The tiers

| tier | name | what is proven | prover | scope |
|---:|---|---|---|---|
| 3 | exact-proven (algebraic) | exact algebraic certificate, **any width** | Clifford stabilizer tableaux | both circuits Clifford |
| 3 | exact-proven (algebraic) | exact GF(2) parity/angle-table equality, **any width** | phase-polynomial tables | both circuits CX+diagonal |
| 2 | exact-proven (numerical full-unitary) | dense \|Tr(A⁺B)\|/d > 1 − 1e-7 | full 2ⁿ×2ⁿ unitaries | ≤ 8q with the optional native wheel, ≤ 6q without (`compactq.equivalence._MAX_QUBITS`) |
| 2 | exact-proven (decision-diagram) | same fidelity rule on QMDD-style decision diagrams | hash-consed DD with a 400k live-node budget | structured circuits up to 32q (hard cap); practical reach depends on family — see the boundary table |
| 4 | exact-proven (compositional) | per-block dense proof over disjoint components; no 2ⁿ unitary is ever built | union-find block decomposition | circuits whose active qubits partition into blocks each ≤ the dense limit, identical block structure on both sides |
| 1 | verified-randomized | K=32 random product states agree to 1e-8 — probabilistically exact (failure probability far below hardware error rates; the standard cycle-benchmarking argument) | numpy statevector streaming | ≤ 30q (statevector memory ceiling, `verify_large.RAND_MAX_QUBITS`) |
| 0 | unverified | no prover covered this circuit | — | prover declined or unavailable; `equivalent` is `null` |

"Exact-proven" means a machine-checked numerical or algebraic
certificate of unitary equivalence up to global phase.  It is NOT a
formal-proof-assistant certificate (roadmap tier 5).

## The cascade

`verify()` tries provers in this order and returns the FIRST decisive
answer: Clifford tableau → phase-polynomial → dense full-unitary →
compositional → decision-diagram → randomized → tier 0.  Each prover is
sound in both directions on its fragment; a "not equivalent" from a
tier ≥ 2 prover is evidence of real inequivalence, and the optimizer
acts on it by discarding the candidate.

## Boundary table (each row backed by a named test)

| circuit class | width | verdict tier / method | backing test |
|---|---|---|---|
| Clifford circuits | any (tested 5/9/40q) | 3 · `clifford_tableau` | `test_boundary_clifford_tier3_any_width` |
| CX+diagonal (incl. QFT-no-H, Trotter, phase oracles) | any (tested 25q) | 3 · `phase_polynomial` | `test_boundary_phasepoly_tier3_any_width` |
| generic gates | ≤ dense limit (8q native / 6q pure) | 2 · `full_unitary` | `test_boundary_dense_tier2_at_limit` |
| generic structured (QFT, adders, Grover shapes) | dense limit < w ≤ ~18q (QFT family; family-dependent) | 2 · `dd_full_unitary` | `test_boundary_dd_tier2_beyond_dense` |
| generic structured | > DD reach, ≤ 32q | declines DD → 1 · `randomized_sampling` (numpy) or 0 · `prover_unavailable` | decline semantics: `test_boundary_budget_blowup_declines` (reduced budget); default-budget reach per family is measured in `results/dd_ceiling.json`, not asserted |
| any | > 32q (`DD_MAX_QUBITS`) | DD out of scope by design → 1 or 0 | `test_boundary_dd_width_cap` (33q) |
| any | > 30q | randomized tier unavailable (memory) → 0 | `RAND_MAX_QUBITS` guard, `tests/test_adversarial_v024.py` |
| block-structured (disjoint blocks ≤ dense limit) | any | 4 · `compositional_disjoint_blocks` | `test_verify_cascade_tiers` in `tests/run_tests.py` |
| non-unitary (measure/reset/classical control) | any | rejected loudly with `UnsupportedCircuitError`, never dropped | `test_boundary_non_unitary_rejected_at_edge` |

The measured per-family DD reach (which widths prove in practice, with
node counts and wall times) is regenerated by
`python scripts/dd_ceiling_bench.py` into `results/dd_ceiling.json|.md`;
the v0.2.4 numbers: QFT proves to 18q (declines at 20q), Grover-MCX to
12q (declines at 14q), Trotter rings and GHZ to the full tested range
(30q).

## What the user sees on a decline — the loud-failure contract

A prover that cannot decide **declines**; it never guesses.

* `optimize(circ)` / `optimize_search(circ)`: every rewrite is exact by
  construction, and the whole-circuit proof runs inside the prover
  limits.  On any numerical doubt the candidate is discarded and the
  **original circuit is returned unchanged** — the never-grow contract
  means a declined proof costs you the optimization, never your
  correctness.
* `optimize_large(circ)` returns `(circuit, status)`; the status strings
  are exactly `exact-proven (algebraic)`,
  `exact-proven (decision-diagram)`, `exact` (randomized), or
  `rejected` (original returned).  There is no "probably fine" status.
* `verify()` at tier 0 returns `equivalent: null` with method
  `prover_unavailable` — a loud `None`, not a boolean guess.
* The DD prover's decline contract is three-dimensional: the **node
  budget** (memory; default 400k live nodes, overridable with
  `$COMPACTQ_DD_MAX_NODES` so constrained machines can trade proof
  reach for a smaller footprint — a smaller budget only widens the
  decline surface, never a verdict), and a **wall-clock deadline**
  (decline latency, default 120 s in the `verify()`/`optimize_large`
  cascades, override with `$COMPACTQ_DD_DEADLINE_S`; unset it for the
  historical unbounded behavior).  Either one raises `DDOverflow` and
  the cascade moves on — below the deadline, verdicts are
  deterministic.  The same decline path is exercised by tests
  (`test_dd_beyond_ceiling` in `tests/run_tests.py`,
  `test_boundary_budget_blowup_declines` in
  `tests/test_tier_boundaries.py`).  If the randomized tier then
  cannot run either (statevector memory), the cascade returns tier 0
  (`prover_unavailable`) or, in `optimize_large`, status
  `unverified (prover declined)` with the original returned.

## Certificates and the independent checker

`compactq.cert.optimize_with_certificate(circ)` attaches the strongest
whole-circuit witness the provers support (`unitary` ≤ 8q,
`stabilizer`/`phase_polynomial` any width, `dd` ≤ 32q) to the output.
Certificates are re-derived from scratch by the separate
**compactq-check** program, which shares no code with this package —
see [compactq-check/INDEPENDENCE.md](compactq-check/INDEPENDENCE.md)
for the implementation-independence audit and its residual-risk
discussion.

Found a circuit where Compact's verdict is wrong, or a boundary this
table states incorrectly?  That is exactly the report we want — see
[CORRECTNESS.md](CORRECTNESS.md) for the fast path.
